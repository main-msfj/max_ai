Minimum Viable Harness

For a functional coding agent, the smallest useful composition is:

1. Agent Loop

Call model, classify final/tool output, continue until stop.

2. Model Adapter

Normalize model API, streaming and tool-call schema.

3. Context Manager

Instructions, history, repository/file snippets and tool results.

4. Tool Registry

Names, schemas, capabilities and dispatch targets.

5. Tool Executor

Run read/edit/shell tools and capture structured results.

6. Workspace

Working directory, repository and process boundary.

7. Permission Layer

Allow, deny, approval and capability scoping.

8. State

Transcript, turn state and durable workspace changes.

9. Verification

Tests/build/lint commands or explicit checks.

10. Human Approval

Interrupt and resume at risky operations or plan checkpoints.

Production Harness

Add sandboxing, subagents, MCP, skills, hooks, plugins, tracing, observability, context compaction, checkpointing, cost controls and retry/recovery. Each should be a separate policy-visible component, not hidden inside the model adapter.

Recommendation for a new harness in 2026

1 · Make execution capability-based

Every tool declares read/write, network, process and secret capabilities. Enforce at the sandbox boundary; use prompts as a UX layer, not the only security boundary.

2 · Treat context as a managed resource

Keep an append-only event log, derive model context from it, compact explicitly, and expose what was loaded. Separate instructions, user data, tool output and untrusted repository text.

3 · Keep the loop boring

One typed turn state machine for final/tool/handoff/interrupt/error; deterministic cancellation, budgets and retries. Model-specific reasoning belongs behind the adapter.

4 · Make every decision observable

Trace model calls, tool calls, permission decisions, subprocesses, tokens, latency and state transitions with sensitive-data controls.

5 · Verification is a separate contract

Let the harness run configured checks and present evidence; distinguish “the model says done” from “tests/build passed”.

6 · Extend through typed boundaries

MCP, skills, plugins and subagents should compile into the same registry/policy/trace model as built-ins.

Consistently present: loop, context, model adapter, tool registry, dispatcher, workspace, state and some policy boundary. Optional: subagents, MCP, skills, plugins, sandbox depth, tracing, compaction and durable memory. Differentiators: Claude’s instruction/extension/permission control plane; Grok’s open Rust runtime and workspace/tool crate split; Agents SDK’s reusable Runner, handoffs, sessions, guardrails and tracing; Codex’s explicit local sandbox/approval/thread event architecture.
