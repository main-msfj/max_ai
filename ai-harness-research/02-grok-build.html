Grok Build

Open-source Rust coding-agent harness and fullscreen TUI. The repository exposes much more of the runtime than the other closed CLIs: composition root, agent shell, tools, workspace/VCS/execution, configuration, MCP, sandbox and extensions.

VERIFIED: public Rust sourceApache-2.0 first-partyRustCLI / TUI / headless / ACP

Purpose

Understand a codebase, edit files, execute shell commands, search the web and manage long-running coding tasks.

Official repository

xai-org/grok-build; docs at docs.x.ai/build.

Model boundary

Grok Build is the harness. The Grok model/API supplies generation, reasoning and tool-call decisions; the Rust runtime executes tools.

2. Architecture overview

The repository README names the runtime and its crate boundaries. This diagram follows those published boundaries and marks extension points around the loop.

3. Component map

A · Runtime VERIFIED

xai-grok-shell is explicitly “agent runtime + leader/stdio/headless entry points”. Long-running tasks and headless modes are documented. Exact stop/retry policy is UNKNOWN unless read from a specific current source file.

B/C · Model + context VERIFIED

Rust runtime assembles repository/workspace context, conversation state, tool definitions, skills, plugins and MCP. Model capability (reasoning, streaming and function/tool calling) belongs to the xAI API; dispatch and context are harness work. Public docs do not prove an internal semantic index.

D/E · Tools / dispatch VERIFIED

Repository names terminal, file edit and search tools, with a tool crate and MCP support. The model call produces a tool request; Rust resolves a registry entry, applies policy and invokes the tool. Exact parser traits and error-retry rules are UNKNOWN.

F · Environment VERIFIED

xai-grok-workspace covers host filesystem, VCS, execution and checkpoints. The runtime also has sandbox documentation. OS controls and released sandbox mechanisms depend on platform.

G · Security VERIFIED

Sandboxing, configuration and permission surfaces are part of the published CLI closure. Exact default approval matrix and command classifier are UNKNOWN from the top-level README; inspect the crate/docs version used in deployment.

H · Verification INFERRED

Command outputs, tests and checkpoints are available to the agent. No public README claim establishes a universal independent verifier; verification is likely tool/workflow driven.

I · State VERIFIED

Workspace/VCS state and checkpoints are explicit. Conversation/session persistence is part of the runtime surface; durable long-term memory beyond repo state is UNKNOWN.

J · Subagents UNKNOWN

The repository layout mentions extension support and the user guide names skills/plugins/hooks/MCP, but the top-level primary sources reviewed here do not establish a subagent API. Treat subagents as unknown until the exact docs/source path is inspected.

K/L · Hooks / extensions VERIFIED

User guide ships with configuration, slash commands, MCP servers, skills, plugins, hooks, headless mode and sandboxing. These are first-class extension surfaces around the core runtime.

M/N · Observability / human

VERIFIED TUI, stdio, headless and ACP provide interaction/transport. Logging and event details are UNKNOWN at repository top level. Human approval is INFERRED where sandbox/permission prompts are active.

4. Execution loop + 5. data flow

prompt + workspace metadata + instructions → agent runtime → xAI model API; tool call → tool registry → sandbox/permission → tool executor; tool result + checkpoint → session/workspace state → next model input; final response → TUI, headless stdout or ACP.

6. Code structure

crates/codegen/xai-grok-pager-bin

Tool implementations: terminal, file edit, search and related tool-layer code.

crates/codegen/xai-grok-workspace

Host filesystem, VCS, execution and checkpoints.
