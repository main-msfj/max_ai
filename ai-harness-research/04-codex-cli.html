OpenAI Codex CLI

Open-source Rust coding agent that runs locally in the terminal. Its distinctive public architecture is the tight coupling of agent turns with a platform sandbox, approval policy, workspace trust, command execution and streamed event state.

VERIFIED: public Rust sourceApache-2.0Rust-firstTUI / CLI / SDK

Official repository

openai/codex

Purpose

Inspect and modify a local repository through model-generated commands and patches, with sandbox and approval boundaries.

Model boundary

The model/API generates responses, reasoning and tool calls. Codex owns thread lifecycle, tool execution, approvals, sandboxing and event delivery.

3. Component map

A · Agent runtime VERIFIED

Public SDK exposes thread_start/thread_resume and turn run/stream/interrupt/steer. Core CLI iterates model output and tool calls; sandbox/approval failures feed back as events/results. Exact internal stopping classifier is UNKNOWN.

B/C · Model + context VERIFIED

Codex builds instructions/history/tool input around a thread. Repository instructions use AGENTS.md conventions in the source/docs. Context compaction details are UNKNOWN in the public top-level docs; do not assume a summarizer.

D/E · Tools / dispatch VERIFIED

Terminal/shell execution, patch/editing and file inspection are core. MCP is configured through CLI/config. Model tool requests are converted into typed notifications and dispatched through the core; tool names and internal module boundaries are version-sensitive.

G · Sandbox / permissions VERIFIED

Modes include read-only, workspace-write and full-access; approval policies include on-request, never and related presets. Trusting a workspace changes defaults. YOLO bypasses approvals and sandbox and is explicitly dangerous.

F · Environment VERIFIED

Current directory and configured writable roots form the workspace; shell processes run under a platform-dependent sandbox. Network is disabled by default in workspace-write unless enabled.

H · Verification INFERRED

Command output and tests are returned to the model; repository correctness is generally verified by commands the agent runs. No universal independent verifier is established by the public CLI contract.

I · State VERIFIED

Threads, turn IDs, streamed notifications, resume and steer/interrupt state are explicit. Filesystem, git and configuration are external/persistent state. Long-term memory database is UNKNOWN.

J · Subagents UNKNOWN

The public repository has active development and SDK surfaces, but this page makes no claim of a stable subagent API without a version-pinned official source reference.

K/L · Hooks / extensions VERIFIED

Configuration, MCP and hooks are present in the repository/CLI surface. Skills and custom agents are UNKNOWN as core Codex CLI primitives; do not borrow Claude terminology.

M/N · Observability / human

VERIFIED Streamed notifications expose turn/tool lifecycle; TUI shows progress, approvals and errors. Human approval is a first-class branch before risky execution.

4. Complete execution flow + 5. data flow

user input + config + AGENTS.md → core thread/turn → model transport; tool call → approval policy → platform sandbox → shell/patch/MCP; stdout/stderr/diff → event stream + thread history → next turn; final → TUI/SDK result.

6. Code structure

codex-rs/core

Core agent lifecycle, turn state, model interaction and notifications; exact file names evolve with releases.

codex-rs/exec / tools

Shell/command execution and tool dispatch paths.

codex-rs/sandboxing

Platform-specific sandbox backends and policy integration.

codex-rs/utils

CLI options, config, environment policies and shared types such as sandbox/approval enums.

codex-rs/tui

Interactive terminal UI and event rendering.

sdk/

Python/other SDK surfaces for threads, turns, streaming and sandbox overrides.
