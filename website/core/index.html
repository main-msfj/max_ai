Core runtime

The typed state and orchestration inside the harness. These modules explain how a full conversation survives repeated model calls, tool actions, and pauses.

RunContext: the conversation state#

RunContext lives in max_ai.types and is the state passed between turns. It holds user_id, session_id, run_id, live messages, older message history, tool state, plan, compaction state, runtime state, and gate evidence. The Agent binds memory and workspace access to its user/session IDs.

Two turns in one conversation
ctx = RunContext(user_id="u1", session_id="support-42")
first = await agent.run("Review this order", run_context=ctx)
second = await agent.run("Now summarize the result", run_context=first.context)

A new task keeps the conversation messages. Tool calls pending approval must be resolved before adding a new task. Runs in the same user/session are serialized; other sessions can overlap.

Sessions: load, run, save#

The Agent never touches storage — the host owns the RunContext lifecycle: load it before the turn, run the agent, save the result after. LocalSessionStore (max_ai.capabilities.session_store) implements this on disk; a MongoDB-backed store follows the same CoreSessionStore contract.

Host-owned session lifecycle
from max_ai.capabilities.session_store import LocalSessionStore

store = LocalSessionStore(base_path="./agent-data")
ctx = await store.load(user_id, session_id) or RunContext(user_id=user_id, session_id=session_id)
response = await agent.run(text, run_context=ctx)
await store.save(response.context)

This keeps the Agent stateless and reusable across requests: any process can load a saved RunContext, continue the conversation, and save it back, which is what lets one Agent instance serve many users concurrently.

Embeddings and retrieval#

CoreEmbedding (max_ai.base.embedding) turns text into vectors, in batches and with a cache, so memory and knowledge backends can search by meaning instead of exact text, in any language. It is infrastructure passed to a registry's embedding= argument, not an Agent constructor input.

LocalFastEmbedEmbeddingRuns a small multilingual model on-device. pip install "maxai[embeddings]". The default when knowledge search needs one.
APIOpenAIEmbeddingNo model download — better for serverless deployments. Same CoreEmbedding contract.

Knowledge search uses one by default (local); memory only embeds when given one explicitly. The SQLite and MongoDB backends store each vector next to its record, so nothing is re-embedded after a restart — and MongoDBMemoryRegistry/MongoDBKnowledgeRegistry use MongoDB's native $vectorSearch when the server supports it (Atlas, or the mongodb/mongodb-atlas-local image), falling back to ranking in Python otherwise.

Memory that searches by meaning
from max_ai.capabilities.memory.local import LocalMemoryRegistry
from max_ai.core.embeddings import FastEmbedEmbedding

memory = LocalMemoryRegistry(base_path="./agent-data", embedding=FastEmbedEmbedding())
# search_memory now matches paraphrases and other languages, not just substrings.
