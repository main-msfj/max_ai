Agents

Define an agent's identity, model client, tools, and execution policy. Then run a task or resume an existing run.

Agent configuration#

Agent needs an identity and a model client. The remaining arguments plug in tools, MCP connections, execution, context sources, or run policies. Defaults are selected for reasoning, workspace, and execution.

A run accepts task as text, one CoreMessage, a list of messages, or None; it can also receive a RunContext and CancellationToken. Call await agent.run(task, run_context=...) for a result. Use run_stream() for text chunks, run_stream_events() for structured events, and resume(run_context) after an approval or user-input pause. AgentResponse contains final_text, finish_reason, usage, and the run context.

Run lifecycle#

Task + RunContext→PromptCtx→Reasoning loop→AgentResponse

run() returns a final AgentResponse; run_stream() yields text chunks; run_stream_events() yields runtime events and the final response. A pause for approval or input preserves the run context so the caller can resolve it and resume.

The agent owns its executor sessions. Use it as an async context manager so close() runs when the scope exits.
