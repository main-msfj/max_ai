Base contracts

The stable interfaces behind a pluggable harness. Start here when you want to add a provider or understand which object owns which responsibility.

Where Base fits#

max_ai.base defines what a component must provide. max_ai.capabilities contains implementations that satisfy those contracts. max_ai.core supplies the runtime types and machinery that connect them. Agent is the composition point.

Base contract→Capability implementation→Agent configuration→Core runtime

The contract catalog#

ModelCoreChatCompletionClientA provider-neutral call/stream interface for messages, prompts, tools, and usage.
PromptCoreLayerA Jinja2-backed layer with declared variables and serializable template configuration.
ToolsCoreToolA tool name, description, JSON Schema parameters, approval mode, and async execute method.
ReasonBaseReasoningA per-run bound loop; ReAct supplies the default iterative implementation.
CloseCompletionBaseA gate that observes a turn and decides whether the proposed final answer may close it.
ContextCoreMemoryRegistry, CoreSkillBase, CoreKnowledgeRegistryDistinct contracts for personal memory, packaged procedures, and on-demand retrieval.
RuntimeWorkspaceBase, ExecutorBaseSeparate persistent user files from execution of runtime tools.
ControlCoreCompaction, CoreMiddlewareManage long conversations and intercept run/model/tool lifecycle hooks.
StoresCoreContextRegistry, session and quota storesAdditional storage contracts; context registries are available independently of the current Agent constructor.
ComponentComponentBaseDefines provider identity and config serialization/deserialization for trusted components.

How to implement one#

Choose the contract for the behavior you want to replace. A concrete class implements its abstract methods and exposes a provider path. Add a Pydantic config schema plus _to_config()/_from_config() when the instance must survive serialization. Runtime data belongs in RunContext or the per-run binding, rather than shared mutable fields on a reusable component.

Shape of a component
class MyLayer(Component[StackConfig], CoreLayer):
    component_schema = StackConfig
    component_type = "prompts"
    # Provide _default_template() and any variable declarations.

Reasoning and middleware contracts#

These contracts receive different parts of a run. Reasoning drives the loop; middleware observes or changes selected lifecycle events.

BaseReasoning: the loop and its inputs

Receives: RunContext (messages, tool records, and run state), a rendered PromptCtx, per-run BaseLoopState, and optional streaming, cancellation, output-format, and evaluation settings. The Agent binds runtime dependencies such as the client, dispatcher, middleware chain, compaction strategy, and memory when a run starts.

Returns: An async stream of CoreEvent objects. A custom loop records assistant and tool messages in the context, registers tool calls before dispatch, and emits a completion event when the turn ends.

Reasoning loop contract
async def execute_reasoning_loop(
    self,
    ctx: RunContext,
    prompts: PromptCtx,
    loop_state: BaseLoopState,
    stream_tokens: bool = False,
    cancellation_token: CancellationToken | None = None,
    output_format: type[BaseModel] | None = None,
    eval_criteria: list[str] | None = None,
    **kwargs: Any,
) -> AsyncGenerator[CoreEvent, None]:
    ...

The default implementation is ReactLoop. Use Agent(reasoning=...) to select a strategy; keep per-run mutable state in the bound loop state or RunContext, not on the reusable strategy object.

CoreMiddleware: run, model, and tool hooks

Receives: Each hook gets a MiddlewareContext with the current RunContext, agent name, event emitter, and a per-run state helper. The second argument depends on the hook: a task at run start, a ModelRequest before a model call, or a ToolRequest before an approved tool call.

Can return: Model hooks may edit requests or responses; returning a replacement ToolResult from on_tool_request skips that tool execution. The default methods do nothing, so a subclass only needs the hooks it uses.

A small run-start middleware
from max_ai.agents import Agent
from max_ai.base.middleware import CoreMiddleware

class RunLogMiddleware(CoreMiddleware):
    async def on_run_start(self, mw, task):
        kind = "new run" if task is not None else "resumed run"
        print(f"{mw.agent}: {kind}")

agent = Agent(..., middlewares=[RunLogMiddleware()])

Use mw.state(self) for state that must survive pause and resume. Middleware receives hooks; a completion gate makes the separate decision to accept or reject a final answer.

Base contracts, explained#

Everything in max_ai.base defines the interfaces that framework components follow. The examples below show what each contract owns and how it is connected to an Agent.

CoreAgentCapabilities: capability base

Receives: A typed configuration schema through its component base. Capability registries can connect to resources during the Agent lifecycle and optionally expose tools.

Use it for: The shared base of memory, knowledge, skills, and workspace capabilities.

Capability contract
class CoreAgentCapabilities(CoreLifecycleComponent[ConfigT], ABC):
    @property
    def tools(self) -> list[CoreTool]:
        return []
CoreChatCompletionClient: model provider

Receives: A model name, optional API key or environment variable, and provider configuration. Its run() method receives rendered prompt context and messages, plus optional tools and streaming settings.

Returns: Normalized completion results or chunks, independent of provider wire formats.

Configure the client contract
from max_ai.agents import Agent
from max_ai.capabilities.clients.openai import OpenAIChatCompletionClient

client = OpenAIChatCompletionClient(
    model="gpt-5.6-luna",
    api_key="YOUR_API_KEY",
)
agent = Agent(..., client=client)
CoreCompaction: conversation history

Receives: The conversation, rendered prompts, token limits, and current compaction state. A strategy implements _compact; shared contract code validates and returns the updated message groups and state.

Use it for: Keeping the conversation within a model's context window while preserving useful earlier details.

Choose a compaction strategy
from max_ai.agents import Agent
from max_ai.capabilities.compaction.window import SlidingWindowCompaction

agent = Agent(..., compaction=SlidingWindowCompaction(
    max_turns=10,
))
CoreKnowledgeRegistry: searchable reference data

Receives: A source name, a description for its search tool, and a query with an optional result limit.

Returns: Matching KnowledgeBlock records. The registry exposes search_{name} when tool access is enabled.

Connect knowledge to an agent
from max_ai.agents import Agent
from max_ai.capabilities.knowledge.local import LocalKnowledgeRegistry

knowledge = LocalKnowledgeRegistry(
    name="product_docs",
    description="Search product documentation.",
    base_path="./agent-data",
)
agent = Agent(..., knowledge=[knowledge])
CoreLayer: prompt content

Receives: Declared variables from the Agent and runtime context. Its Jinja2 template renders into prompt text before the client call.

Use it for: Adding reusable instructions or context while keeping prompt construction composable.

Define a prompt layer
class TeamRulesLayer(CoreLayer):
    def _default_template(self) -> str:
        return "Follow the team rules for {{ team }}."

    def _required_variables(self) -> set[str]:
        return {"team"}
CoreMemoryRegistry: user and session memory

Receives: A user and session scope from RunContext, plus memory records to create, update, list, or search.

Use it for: Information that changes over time and belongs to a particular user or conversation.

Attach memory
from max_ai.agents import Agent
from max_ai.capabilities.memory.local import LocalMemoryRegistry
from max_ai.types.run_context import RunContext

memory = LocalMemoryRegistry(base_path="./agent-data")
agent = Agent(..., memory=memory)
context = RunContext(user_id="user_001", session_id="session_001")
CoreMiddleware: lifecycle hooks

Receives: A middleware context and the event payload for run, model, or tool hooks. Hooks may observe or return an updated request or response.

Use it for: Logging, tracing, request changes, or handling tool results around an Agent run.

Register middleware
from max_ai.agents import Agent
from max_ai.base.middleware import CoreMiddleware

class RunLogMiddleware(CoreMiddleware):
    async def on_run_start(self, mw, task):
        print(mw.agent, "started")

agent = Agent(..., middlewares=[RunLogMiddleware()])
CoreSkillBase: reusable procedures

Receives: A source location and a list of selected skill names. Preparation loads each skill's SKILL.md and metadata into the registry.

Use it for: Giving an Agent task-specific procedures and supporting files that it can consult when needed.

Attach skills
from max_ai.agents import Agent
from max_ai.capabilities.skills.local import LocalSkillRegistry

skills = LocalSkillRegistry(
    source="./skills",
    skills=["invoice-review"],
)
agent = Agent(..., skills=skills)
WorkspaceBase: user files

Receives: A user ID and optional conversation ID at run time. The workspace prepares directories and downloads or uploads files for local or remote storage.

Use it for: Keeping files available between runs for a user, including files used by tools and skills.

Attach a workspace
from max_ai.agents import Agent
from max_ai.capabilities.workspace.local import LocalWorkspace

workspace = LocalWorkspace(root="./agent-data")
agent = Agent(..., workspace=workspace)

For more, see GitHub.
