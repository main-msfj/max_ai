BaseComponent

BaseComponent is the shared contract foundation in max_ai/base. Its ComponentBase class provides component identity, configuration schemas, and serialization hooks used by the provider and capability contracts.

ComponentBase contract#

The shared Python class is ComponentBase[ConfigT]. It provides component identity and serialization hooks for a typed configuration. It is not an abstract class, so these hooks raise NotImplementedError by default instead of being enforced with @abstractmethod. Agent-facing contracts such as memory and knowledge inherit through CoreAgentCapabilities, which adds a lifecycle and the shared capability interface.

Shared component base
class ComponentBase(Generic[ConfigT]):
    component_type: ClassVar[ComponentType]
    component_schema: ClassVar[type[BaseModel]]

    def _to_config(self) -> ConfigT: ...

    @classmethod
    def _from_config(cls, config: ConfigT) -> Self: ...


class MyComponent(ComponentBase[MyConfig]):
    component_type = "my_component"
    component_schema = MyConfig

    def _to_config(self) -> MyConfig:
        return MyConfig(path=self.path)

    @classmethod
    def _from_config(cls, config: MyConfig) -> "MyComponent":
        return cls(path=config.path)

Methods to override

MethodPurpose
_to_config()Return a Pydantic config containing the data needed to rebuild this component. Keep secrets out; serialize environment variable names instead.
_from_config(config)Build a component instance from its validated config.
_from_config_past_version(config, version)Optionally migrate older stored configs. Override when a component changes config schema between versions.

These config hooks raise NotImplementedError by default; Python does not enforce them with @abstractmethod. CoreLifecycleComponent adds async connection hooks, and CoreAgentCapabilities builds on it for agent-facing registries. The individual BaseComponent pages show each contract declaration and its abstract methods.
