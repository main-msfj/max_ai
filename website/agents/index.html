Agent

Agent is the coordinator for one configured assistant. It combines identity and instructions with a model client, then connects the tools, capabilities, and runtime components that the assistant can use.

On each run, Agent prepares the prompt, calls the reasoning loop, routes tool calls, and returns the response and updated context. You can add memory, knowledge, skills, middleware, output rules, a workspace, and an executor as the application needs them.

Agent configuration#

This constructor shows the complete configuration surface. Only name, description, instructions, and client are required; the other components are optional.

Run lifecycle and event stream#

run_stream_events() is the low-level interface for one agent turn. It accepts a task and optional conversation context, then yields lifecycle events as they happen and an AgentResponse at the end. Use it when your application needs to show progress, inspect tool activity, or decide how to handle a paused run.

Agent.run_stream_events
async def run_stream_events(
    self,
    task: str | CoreMessage | list[CoreMessage] | None = None,
    run_context: RunContext | None = None,
    cancellation_token: CancellationToken | None = None,
    stream_tokens: bool = False,
    **kwargs: Any,
) -> AsyncGenerator[CoreEvent | AgentResponse, None]:

The stream ends with an AgentResponse; preceding items are CoreEvent instances. This example keeps a stable user/session identity and prints event types while the run is active.

Consume one session's event stream
from max_ai.agents import Agent
from max_ai.core.event_type import CoreEvent
from max_ai.types.agent_response import AgentResponse
from max_ai.types.run_context import RunContext

context = RunContext(user_id="user_001", session_id="support_session")
response: AgentResponse | None = None

async with agent:
    async for item in agent.run_stream_events(
        task="Summarize the open support request.",
        run_context=context,
        stream_tokens=True,
    ):
        if isinstance(item, AgentResponse):
            response = item
        elif isinstance(item, CoreEvent):
            print(item.event_type)

if response is not None:
    print(response.final_text)
    print(response.finish_reason)

Arguments

ArgumentPurpose
taskA text task, one CoreMessage, a list of messages, or None. This is the new input for the turn; pass messages when you need a non-text or prebuilt conversation input.
run_contextThe RunContext holding user/session IDs, conversation messages, tool state, and runtime state. Reuse it to continue a conversation; if omitted, Agent creates a fresh context.
cancellation_tokenAn optional CancellationToken linked to the run. Trigger it when the caller needs to stop an active turn.
stream_tokensWhen True, the stream includes model token-chunk events as they arrive. Keep it False when only lifecycle and tool events are needed.
kwargsAdditional keyword arguments forwarded to the configured reasoning loop. Use these for loop-specific options.

Events and final response

CoreEvent items describe activity such as a task starting, a reasoning step, a tool call, a model chunk, or a pause. Read event_type to identify the event and inspect its fields for details. The final AgentResponse includes final_text, finish_reason, usage, and the updated context.

If a response needs approval or user input, resolve the pending item in its context before resuming. The application should collect the user's decision; do not start a new task with unresolved tool calls.

Resolve an approval and continue
context = RunContext(user_id="user_001", session_id="support_session")

async with agent:
    response = await agent.run(
        "Send the prepared email?",
        run_context=context,
    )

    if response.needs_approval and response.context is not None:
        pending = response.pending_approvals[0]
        approved_by_user = input("Approve this action? [y/N] ").lower() == "y"
        response.context.tool_state.apply_approval(
            pending.id,
            approved=approved_by_user,
        )
        response = await agent.resume(run_context=response.context)

For a pending question, use response.context.tool_state.apply_user_answer(record.id, answer) and then call agent.resume(run_context=response.context). Resume uses the same conversation and does not add a new task.

Other run methods and cleanup

MethodUse it when
run()You want one final AgentResponse without consuming intermediate events.
run_stream()You want assistant text chunks as they arrive.
run_stream_events()You want typed lifecycle events and the final response in one stream.
resume()You have resolved a pending approval or question and want the same turn to continue.

Use async with agent so the Agent closes managed execution sessions and MCP connections when the scope ends. The default local executor runs on the host; use Docker or Modal when you need an isolated execution environment. See the Executor guide.
